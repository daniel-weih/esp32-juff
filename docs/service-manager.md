# JUFF 服务管理后台

运行 `make admin`，访问 <http://127.0.0.1:3210/>。后台独立于语音服务运行，
启动页面不会自动连接设备、打开麦克风上传或建立 Qwen 语音会话。
可通过 `host/.env` 中的 `JUFF_ADMIN_PORT` 调整端口；监听地址固定为 `127.0.0.1`。

## 助手设定

打开「助手设定」，可直接编辑 Qwen Audio Agent 的助手画像。当前安装的
`qwen-audio-agent@1.11.0` 原生支持 `ASSISTANT.md`，每次新建语音会话时加载；
该文件定义默认名称、性格和表达风格。后台保留 Agent 自身的工具与运行规则。

![助手设定：宽屏编辑器、小智模板和生效说明，使用合成示例](images/juff-admin-assistant.png)

「填入小智设定」会填入草稿：昵称为小智，接受“你好小智”的称呼，回答简短自然；
被问到模型来源时如实说明。它不会更改设备端的 WakeNet 唤醒词。
同一 Qwen 实例下，大小屏和对话控制台共用该画像。对话中明确保存的用户称呼偏好
优先于默认画像；如果曾给助手起过别的名字，可在对话中明确更改该偏好。

- **保存设定**：写入本机文件，下次建立语音会话时读取，当前对话继续。
- **保存并重连**：保存后重新连接后台原本运行的 BLE／Bridge 服务，以创建新的
  语音会话；会短暂断开对话，不启动原本停止的设备，也不重启网关。
- **重新读取**：放弃当前草稿，读取文件中的最新内容。不同页面同时修改或手动
  编辑文件后，过期版本会被拒绝，避免静默覆盖。

内容最多 4000 个 Unicode 字符，与 Agent 的读取上限一致。文件原子替换，权限
`0600`，保留上一版到相邻的 `.previous` 文件；相同内容重复应用不覆盖备份。
采用已安装 Agent 的只读配置解析器，遵循 `QWAUDIO_CONFIG_DIR`、`QWAUDIO_DATA_DIR`、
`XDG_CONFIG_HOME`、本机 `config.env` 和 `QWEN_AUDIO_AGENT_ASSISTANT_PROFILE_PATH`。
默认位置为 `~/.config/qwaudio/ASSISTANT.md`；只读页面不会初始化 Qwen 数据文件。
画像正文只出现在专用接口，不进入状态轮询或运行日志。

外部启动的本机网关仅支持保存默认本机配置，需确认它使用相同配置并在原入口重连。
远程网关需在其所在主机上修改。名称设定无需重新刷写设备固件。

## 服务与设备

后台默认列出 1.54 英寸和 3.5 英寸两个设备配置，可增加到八台。
打开「我的设备」，填写蓝牙连接页显示的 `JUFF-XXXX` 名称。
同一蓝牙名称只能绑定一个配置，Bridge 端口与会话编号也必须各不相同。
只用 Wi-Fi 时可留空蓝牙名称。这里的硬件选择用于组织连接，不会烧录固件。

| 服务 | 查看与操作 |
| --- | --- |
| Qwen Gateway | 查看健康状态、模型、PID 和运行时间；启动、停止、重启 |
| 每台设备的蓝牙语音 | 查看搜索、连接、语音就绪状态和固件、电量、音频指标；独立启停 |
| 每台设备的 Wi-Fi Bridge | 查看监听与设备连接状态；按配置的端口独立启停 |

「一键启动」会启动网关和已绑定设备的蓝牙。Wi-Fi Bridge 按需单独开启，
监听范围沿用 `JUFF_BRIDGE_HOST`；设备上的 Bridge 地址需与这里的端口相符。
固件版本与电量在收到设备状态后显示，离线保留的电量明确标记为上次读数。
大屏不显示其未支持的电池数据。麦克风指标在没有新数据时停止显示。

同一 Qwen 本机用户同一时刻只有一个语音通道；不同会话编号不会增加并发
语音通道。BLE 首次建立会话会申请接管，Wi-Fi Bridge 沿用 `QWEN_TAKEOVER`
设置。多台设备服务可以同时连接，等待中的设备在占用者停止、断开或唤醒
会话超时释放通道后，会自动申请空闲通道。自动恢复不接管仍被占用的通道，
不会让设备互相反复抢占；原有输入／输出设置和麦克风静音状态会保留。
主动静音、休眠或已关闭的会话不会因为通道空闲而自动开启。WAKE 等待期间
若已达到设备的 3 分钟超时，需要再次唤醒；同一次唤醒恢复时不会重复播“我在”。

停止一台设备不会停止其他设备或共享网关。停止网关会先停止它管理的全部
连接服务；重启网关会恢复此前运行的连接服务。外部终端启动的网关和 Bridge
只显示状态，需在原终端停止。请将同一设备的蓝牙连接交给一个启动入口管理。

运行日志只在内存中保留最近 600 条，可按服务与文本筛选；后台重启后清空。
原始麦克风载荷与主机输出的对话文本不进入管理日志，已知凭据会脱敏。
错误仍可能涉及运行环境，分享日志前应查看其内容。

蓝牙播放出现欠载或结束时，`BLE PLAYBACK` 记录该回答的供数和缓冲计数。
`sourceMs` 为 Mac 已收到的音频时长；`receivedMs` 为设备已确认收到的时长；
`hostPendingMs` 包含主机排队和蓝牙在途但尚未确认的数据；`queuedMs` 是设备
缓冲时长。`sourceGapMs` 是已观察到的最大云端分片间隔，`sourceAgeMs` 是距
最近一个分片的时间，`sourceDone` 表示云端已结束合成。欠载发生时，若
`hostPendingMs` 仍很高，应进一步检查主机发送与蓝牙链路；若它为零且合成
未结束，应检查上游供数。该记录只含数值和状态，不保存音频、转写或回答标识。
计数可以帮助定位停顿阶段，不能单独证明无线干扰、系统调度或云端服务是根因。

## 本机配置

设备配置写入 `host/.local/devices.json`，使用原子替换和 `0600` 文件权限。
整个目录由 Git 忽略，仓库检查也会拒绝强制加入的本地状态文件。
后台不返回 `.env` 内容或设备令牌。DashScope Key 继续由 Qwen 的本机配置保存。
修改或移除设备配置前需停止该设备的蓝牙和 Bridge 服务。

停止语音服务不会关闭页面。在启动后台的终端按 `Ctrl-C`，会关闭后台及其
启动的服务；进程清理只作用于它创建的进程组，不按进程名称批量结束其他程序。

## 管理接口

静态页面与接口共享同一本机端口，不开放 CORS。浏览器请求必须使用正确的
Host；写请求还需同源 Origin、JSON Content-Type 和当前实例的 `X-Juff-CSRF`
请求头。令牌由 `GET /api/state` 提供，后台重启后刷新页面重新获取。
这些措施防止外部网站通过浏览器控制本机服务，不是多用户或远程登录系统。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/state` | 服务、设备、环境准备状态与最近日志 |
| `GET /api/logs?service=<id>&after=<序号>` | 按服务或序号读取运行日志 |
| `GET /api/assistant` | 读取助手画像、版本摘要、小智模板及应用条件 |
| `PUT /api/assistant` | 提交 `content`、`revision`，可选 `reconnect: true` 重连运行中的设备 |
| `POST /api/services/<id>/start` | 启动服务及必要网关 |
| `POST /api/services/<id>/stop` | 停止拥有的服务；`all` 停止全部拥有的服务 |
| `POST /api/services/<id>/restart` | 重启服务；网关会恢复先前的关联服务 |
| `POST /api/devices` | 添加设备配置 |
| `PUT /api/devices/<id>` | 更新已停止设备的配置 |
| `DELETE /api/devices/<id>` | 移除已停止设备的配置 |

服务 ID 为 `gateway`、`<设备编号>-ble` 和 `<设备编号>-bridge`。
命令仅映射到项目内固定的可执行程序及参数，不提供任意 shell 执行接口。

## 验证

`cd host && npm test` 包含配置校验、跨站请求拦截、受控生命周期、依赖重启、
日志脱敏、助手设定持久化／版本冲突／重连、已安装 Qwen 提示词加载契约与真实进程组退出测试。
多设备回归使用真实本机 WebSocket 和已安装 Qwen 的会话仲裁代码，覆盖占用
释放、接管后恢复、多个等待者竞争、重复通知、静音和 WAKE 超时。
测试使用本机假网关及合成事件，不需要实体
设备、麦克风或云端账号。前端为原生 HTML/CSS/JavaScript，无额外构建依赖。

2026-09-07 的实机检查还让大小屏同时连接上述本机模拟网关：大屏接管后，小屏
保持连接并等待；结束大屏会话后，小屏在原 WebSocket 上以不接管的方式重新
申请成功，恢复麦克风传输，随后一段本地提示音完整播完，没有新增欠载或丢
音频。该检查运行正式主机与 BLE 程序、使用真实设备，未连接云端，收到的
麦克风载荷立即丢弃；它验证通道恢复，不构成云端服务或长期声学可靠性验收。
